# UE 学习实验的维护约定

- 用户学习真实 UE C++，不要用同名标准 C++ 模型替换真实 API。
- 开始前读 README.md、docs/memory/MEMORY.md；新课按真实工具链先探针再出题。
- 普通实验放 examples，每次只构建选中的实验；不要手工编辑生成的 ActiveExperiment.cpp、ActiveExercise.inl 或 ActiveLesson。
- 答题文件只提供声明与提示，由用户实现。AI 可写 test、README 和独立 solution_，不得用参考答案覆盖用户答题。
- 新课程按独立 level 1/2/3 验收，先运行参考答案，再确认初始未答题状态确实失败。测试应检查输出/不变量，避免仅复写实现。
- 参数与调用关系必须有业务契约、边界和可观察证据。不锁定未保证的容量公式、对象地址、线程调度或机器时间。
- 本地序列化、压缩、线程实验只支持当前路径的结论。网络、认证/加密、World 生命周期、渲染线程、GPU 各需自己的运行环境和验收。
- 修改引擎安装、下载源码、启用网络服务或增加重型依赖不属于日常实验的默认步骤。
- 本机用 CMD + Node，PowerShell 在当前执行环境有 CET 崩溃。构建通过引擎自带 UBT，不直接对 UE 文件运行 cl。
- 保留构建失败门禁和实验对象强制重编策略：UE 5.6 UBT 有 1 秒时间戳容差，快速切换源文件可能错误复用旧对象。
- 更新验证状态时区分 example、solution 与 learner，记录当前实际通过和仍未实现的阶段。
