## 已遇到的非显而易见问题

- **FName 大小依赖当前配置。** 本机当前构建的 `sizeof(FName)` 为 12 字节；不能把教学模型的两个整数或其他配置的 8 字节当成固定布局。探针应继续报告实际值，不把该数值写成跨版本断言。
- **UObject 本身是抽象类。** UE 5.6 中不能直接把 `NewObject<UObject>` 当作可实例化基线。`lifetime` 使用正式声明的 `ULabObject` 派生类，验证 `SampleValue` 的真实反射值，再研究 Root、GC 和弱回调。裸局部指针不会自动形成 GC 可见的强引用。
- **归档 API 不自动成为不可信协议解析器。** `SerializeIntPacked` 用于本实验的真实归档写入；损坏或任意输入不直接交给其读取路径。`transport` 已添加最多五字节的 `ReadPacked`，每次读取前检查剩余长度，并拒绝未终止、截断和超出 `uint32` 范围的表示。外层也检查长度、版本、条数和大小上限后才分配。这仍是本地实验格式，尚未承诺跨端或跨版本兼容。
- **Task.Wait 不证明任务在工作线程执行。** UE 任务等待可能在等待线程上内联执行尚未运行的任务。`flow` 先等待工作任务触发的事件，再 `Task.Wait`/取结果，并比较线程 ID，验证转换实际在不同的工作线程发生。该阻塞模式为了展示数据所有权和完成顺序；实时游戏后续需研究 continuation、取消和背压。
- **压缩成功不等于压缩有收益。** 当前传输实验比较实际长度，压缩变大时保留未压缩 payload。`wire_bytes` 仅为实验 envelope 与 payload 长度，不包括真实网络包开销。
- **计时范围必须解释。** `wallMs` 包含引擎启动与退出；`experiment_ms` 是实验内部时间；`transport.codec_ms` 还包含该进程首次压缩器初始化与编解码/校验成本。参数扫描应用重复运行和不同数据分布复查，不能直接把单次值解释为生产吞吐量。
- **快速换源文件会遇到 UBT 的一秒时间戳容差。** 实测空答题链接失败后立即切回 probe，源文件只比旧对象新约 0.719 秒，UBT 跳过编译并再次链接了旧对象。脚本每次构建前只移除本项目 UELab 目录的 ActiveExperiment.cpp.obj，强制重编当前实验，保留宿主、PCH 与引擎缓存。最终日志确认存在 Compile ActiveExperiment.cpp，失败→恢复通过。

## 未实现与不可推导的结论

- Commandlet 不自动提供正常游戏 World、Actor 生命周期和帧循环；World/Timer/Tick runner 是后续阶段。
- 尚未完成真实 NetDriver、多进程客户端/服务端、RPC、属性复制、Fast Array、丢包、迟加入与重连整合。
- 本地序列化和压缩只验证数据处理。它们不等于真实传输协议、认证、网络加密、完整性与重放保护。
- NullRHI 下不能证明 GPU 执行、真实资源上传、视觉效果或 GPU 性能；CPU 渲染线程交接也需单独的运行环境。
- MMORPG/SLG 的参数必须结合输入分布、数值范围、误差、带宽与延迟预算重新测量，示例参数不直接作为生产建议。
- SLG 后端持久化、事务、跨服务一致性和故障恢复需要独立场景。
